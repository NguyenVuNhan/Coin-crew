# Budgets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (\`- [ ]\`) syntax for tracking. In this repo, implementer tasks run as Orca workers through the \`gemini-execution\` skill (\`~/.agents/skills/gemini-execution/SKILL.md\`); the planner reviews every diff and runs the tests.

**Goal:** Budgets for the personal spending book (issue #116): a limit per category or tag and period, with progress, pace, ordering, history, a limit suggestion, and a warning in the entry form.

**Architecture:** Pure budget logic lives in \`@cc/core\` (\`budgets.ts\`) and gets its spending rows from one new additive export of the report engine (\`reports.ts\`), so budgets never count money a second way. Budget definitions are stored in three new D1 tables behind \`requirePersonal\`; progress is computed in the browser from the synced local copy (0 D1 reads), with a server fallback route that runs the same core code. Screens live in \`@cc/web-screens\`.

**Tech Stack:** TypeScript, Hono + Drizzle on Cloudflare D1 (vitest \`cloudflare:test\`), React 19 + React Query, Tailwind v4 / shadcn wrappers, Playwright.

**Spec:** \`docs/superpowers/specs/2026-11-26-budgets-design.md\` (decisions B1–B21, screens §4, data §6, cost §7, tests §8). Mockups: \`docs/superpowers/mockups/budgets/\`.

## Global Constraints

- The 11 Phase 2 rules of issue #116 apply. In particular: **additive migrations only** (new tables; never a column on an existing table); **do not edit** \`commitTripWrite\` / \`guardedTripWrite\`, \`computeBalances\`, \`computeShares\`, \`suggestTransfers\`, \`getSnapshot\`, \`apps/api/src/me/{balances,settle,ledger}.ts\`, \`libs/api/auth/src/device.ts\`, or the expense and payment routes; **never edit or delete an existing test**; ≤ 50 queries per request; no push/SMS/email about budgets; never use the word "ledger" in new names.
- Money is a whole number in the currency's smallest unit; never a float. Fractions (elapsed share, percentages) are computed, never stored.
- Dates are local \`YYYY-MM-DD\` strings; "today" comes from \`todayLocal()\` on the web and a \`today\` query param on the server, as reports do.
- Thresholds (spec B6, B7, B12): near ≥ **0.85** of the limit; too fast when \`spent / elapsed ≥ 1.10 × limit\`; no "too fast" in the first **2 days**, and for periods longer than **92 days** not in the first **5%** either; suggestion after **6** completed periods all over, or all under **0.80**; VND suggestions round to **100.000**.
- Weeks are Monday–Sunday. Monthly start day 1–31; a start day past a month's end is that month's last day.
- Every personal route uses \`requirePersonal\` and scopes by \`user.id\`. Unknown or foreign ids return 404.
- UI: app wrappers first (\`Button\`, \`Sheet\`, \`Pill\`, \`Icon\`, \`EmptyState\`, \`Snackbar\` via \`showUndo\`), theme tokens only (no raw hex; \`style-guard.test.ts\`), \`min-h-11\` touch targets, \`text-base\` fields, money in \`tabular-nums\`, phones first at 375px. Vietnamese first; every new \`vi.ts\` line ends with \`// REVIEW\`. Tests select by \`fsl-*\` classes and \`data-testid\`.
- Lint only through Nx: \`npm run lint\`. Full gate: \`npm test\`, \`npm run typecheck\`, \`npm run lint\`, \`npm run e2e -- golden-path\`, \`npm run e2e -- walkthrough\`.

## Review Focus

1. **A budget created mid-period** (B18): the current period still counts spending from that period's start, history starts there, and no suggestion is possible before 6 full periods exist. → test in Task 2.
2. **Start day 29–31 across February and 30-day months, and the period containing today when today is the start day itself.** → tests in Task 2.
3. **A group share whose wallet resolves to \`null\`** (no default wallet) or to a wallet the budget leaves out: it must not count, and must not crash. → test in Task 1.
4. **Deleting a category, tag or wallet a budget uses**: a category or tag budget is removed with its target; a deleted wallet just stops counting; the Budgets page never shows a broken row. → test in Task 4.
5. **The entry warning while editing an existing expense**: the expense being edited must not be counted twice (its saved amount is replaced by the new one). → test in Task 3.

  export type BudgetPeriodKind = 'week' | 'month' | 'year' | 'once';
  export type BudgetTarget = { kind: 'category'; categoryId: string } | { kind: 'tag'; tagId: string };
  export interface BudgetLimit { effectiveFrom: string; amount: number } // effectiveFrom = a period's start date
  export interface BudgetDef {
    id: string; name: string; target: BudgetTarget; currency: CurrencyCode;
    periodKind: BudgetPeriodKind; monthStartDay: number | null; // month only
    from: string | null; to: string | null;                     // once only, inclusive
    excludedWalletIds: string[]; limits: BudgetLimit[];         // limits sorted by effectiveFrom asc
    suggestionDismissedUntil: string | null;                    // a period start
    createdOn: string;                                          // local YYYY-MM-DD of creation
  }
  export interface BudgetPeriod { from: string; to: string }   // inclusive
  export type BudgetState = 'over' | 'fast' | 'near' | 'fine';
  export interface BudgetProgress {
    budgetId: string; period: BudgetPeriod; limit: number; spent: number;
    left: number;                 // limit - spent (negative when over)
    elapsed: number;              // 0..1, days up to and including today / period days (1 for past periods)
    daysLeft: number;             // including today; 0 for past periods
    state: BudgetState;
    projectedOverPct: number | null; // (spent/elapsed - limit)/limit, when state === 'fast'
    pace: { unit: 'day' | 'month'; amount: number } | null; // null when over or period ended
    ended: boolean;               // once-budget whose range is before today
  }
  export function budgetPeriodAt(def: BudgetDef, date: string): BudgetPeriod | null; // null outside a once range
  export function firstBudgetPeriod(def: BudgetDef): BudgetPeriod;                    // the period containing createdOn (B18); once: its range
  export function budgetPeriodsUpTo(def: BudgetDef, today: string): BudgetPeriod[];   // first..current, newest first
  export function limitFor(def: BudgetDef, period: BudgetPeriod): number;             // latest limit with effectiveFrom <= period.from
  export function budgetSpent(def: BudgetDef, rows: CountedSpendRow[], period: BudgetPeriod, categories: CategoryView[]): number;
  export function budgetProgress(def: BudgetDef, spent: number, period: BudgetPeriod, today: string): BudgetProgress;
  export function orderBudgets(list: BudgetProgress[]): { over: BudgetProgress[]; fast: BudgetProgress[]; onPace: BudgetProgress[]; ended: BudgetProgress[] };
  export const BUDGET_NEAR = 0.85, BUDGET_FAST_MARGIN = 1.1, BUDGET_SUGGEST_RUN = 6, BUDGET_UNDER = 0.8;
  \`\`\`

  Pace (B9): \`left / daysLeft\` per day, rounded down to the currency's smallest unit; periods longer than 31 days use \`left / monthsLeft\` (calendar months left including the current one) with \`unit: 'month'\`.
  Order (B10): over by \`spent/limit\` desc; fast by \`projectedOverPct\` desc; onPace (near + fine) by \`spent/limit\` desc; ended last.
