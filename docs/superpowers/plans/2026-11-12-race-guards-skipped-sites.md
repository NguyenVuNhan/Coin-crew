# Race guards: sites deliberately left alone (participants, proposals)

- `apps/api/src/participants/routes.ts` ~1028 (`POST /trips/:id/membership` insert count): an INSERT…SELECT row count that picks the error message, not a status-change guard; it is issue #80's route and is being changed in another worktree.
- `apps/api/src/participants/routes.ts` ~1127 (membership approve, claimer already a member): approve is followed by a read, then `mergeParticipants` (its own batch), with compensating writes (`pending` / `rejected`) on failure; chained into another batch, so left as is per the spec.
- `apps/api/src/participants/routes.ts` ~1167 (membership approve, plain branch): the approve write is chained to the link step (the link and trip commit are one guarded batch now, and a link miss writes `rejected` back), so the approve stays a separate guarded update with its compensating write.
- `apps/api/src/participants/routes.ts` "Same as X" branch of `POST /people/:pid/approve`: calls `mergeParticipants` (its own guard; owned by the merge-guard task).
- `apps/api/src/proposals/routes.ts` ~177 (`/me/proposals/:id/accept`) and ~230 (`/trips/:id/proposals/:pid/approve`): they only set a side's accepted-at flag; the trip write (activity, version) happens in `completeIfReady` only when the last side accepts, so there is no activity row to batch with the flag. Forcing one would add a log entry and version bump the flow does not have today.
- `apps/api/src/proposals/routes.ts` ~135 (`decide` for cancel): a cancel writes no activity or version bump, so there is no trip write to make atomic; it stays a single conditional UPDATE. Decline and admin reject use `guardedTripWrite`.
- `apps/api/src/proposals/store.ts` ~46 (`insertProposal` insert count): INSERT…SELECT row count used to pick the error message, not a status guard.
- `apps/api/src/proposals/store.ts` ~130 (claim before `mergeParticipants`) and ~162 (link miss): claim, then merge or link, with compensating writes back to `pending` / `cancelled`; the chain spans another batch, per the spec. The trailing `commitTripWrite` could not join the merge's batch without restructuring `mergeParticipants`.
